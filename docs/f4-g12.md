# Feature 4 — Pricing & Fare Rules (Iteration-03)

Oct 6, 2026 · @Zayar

**Live prototype:** [staff-web — Pricing & Finance](https://claude.ai/artifact/NQrNC7hFPa1brQ868ZhaM5) (five interactive pages, sample data)

## Overview

Feature 4 turns a flight and a fare class into a quote: a price per passenger, a line-by-line breakdown of how that price was reached, and a hold window during which the price is guaranteed. It also owns the reference data behind those prices and the monthly financial report (revenue, costs, profit), for the Flython platform. It has two actors:

- **Staff** — maintain fare classes and their restrictions, base fares, taxes/surcharges/fees, the ordered dynamic-pricing rule list, the fixed currency-rate table, promo/corporate codes, and the expense and payment-schedule records behind the financial report, all from staff-web screens owned by this feature.
- **System callers** — feature 3a requests a quote per itinerary leg, 3b stores the `quote_id` on the PNR, and 5b reads the cancellation/change fee rules attached to that quote. Feature 14 reads the monthly financial summary produced here and builds its dashboards on top. Passengers have no screen here; they only see prices inside search and checkout.

**In scope (core):** fare classes, base fares (the foundation price), a rule engine that adjusts the base fare by urgency (H-1, H-3, H-7, H-30), seat load, month, pricing period and seat position, taxes/surcharges/fees, the fare-quote API with its hold window and audit trail, display-only currency conversion from a fixed rate table, and a monthly financial report (revenue, maintenance, staff, catering and other costs, profit) shared with feature 14.

**In scope (stretch items, chosen for this iteration):** fare-rule validation (advance-purchase window, class restrictions), promo codes / corporate rates, and cancellation/change fee rules.

Authentication is out of scope for this feature; routes only carry a guard label. One cross-cutting rule does apply: every time calculation (days to departure, quote expiry) reads the shared simulation clock from feature 1, never the system clock.

## Pricing engine

A quote is built in a fixed order — base fare, rule engine, seat fee, promo, taxes — and every step is saved as a line, so any price can be explained after the fact.

&#91;image: Fare quote flow\]

A repeat request for the same flight, fare class, promo and seat type returns the stored quote until it expires. That stored row is the cache, so no separate cache service is needed. The hold window is `expires_at = created_at + quote_hold_minutes`, both read from the simulation clock, so jumping the clock forward in a demo expires quotes the same way real time would.

### Rule engine

The base fare for the route and fare class is the foundation price. Pricing rules (one row each in pricing\_rule, explained below) then adjust it by four things: how close the flight is (urgency), how full it is (load), the departure month, and any pricing period (a named date range such as a holiday). Each rule belongs to one group. Within a group the first matching rule by priority wins, so the H-1, H-3, H-7 and H-30 tiers never stack; the winning adjustments of different groups multiply.

| Group | Decides on | Example rules (illustrative starting values, tune with the team) |
| --- | --- | --- |
| urgency | days between simulated today and departure | H-1 (0–1 days) +30%, H-3 (2–3) +20%, H-7 (4–7) +10%, H-30 (8–30) +5%, more than 30 days out −10% |
| load | seats left ÷ seats in the cabin, from 3b | under 10% left +25%, under 20% left +15%, over 80% left −10% |
| month | month of the departure date | December +10%, September −5% |
| period | departure date inside the rule's start and end date | Songkran (11–17 Apr) +20%, rainy-season lull −10% |

Seat position is not a rule group: the passenger's seat type adds a flat `seat_fee` (normal, exit row, extra legroom) after the rules, because it depends on a seat choice, not on the flight.

```latex
P = B \cdot (1+u)(1+l)(1+m)(1+p) \qquad S = P + F_{seat} \qquad T = (S - D) + \text{taxes and fees}
```

In the formula, B is the base fare; u, l, m and p are the winning adjustments of the urgency, load, month and period groups (0 when none matches); F\_seat is the seat fee; S is the subtotal before promo; D is the promo discount. A percent promo takes that percent of S, and a fixed promo takes its amount capped at S, so S − D never goes below 0. Every amount is in the quote's currency.

**Calculation rules**

- **Days to departure:** calendar days from the simulated date to the departure date, both read as dates in the origin airport's local time. A flight whose departure timestamp is at or before simulated now is rejected with `FLIGHT_DEPARTED` before any rule runs.
- **Rounding:** each step is rounded half-up to 2 decimals and saved as its own line, so the lines always add up to the total. A display currency rounds to its own minor unit and is never stored.
- **Promo:** a code has either `discount_pct` or `discount_amount`, never both. It applies to price plus seat fee, per passenger, and counts once per booking.
- **Tax base:** every percent tax and surcharge uses the same discounted subtotal (S − D) and they do not compound on each other. Flat taxes and fees are charged per passenger per leg.
- **Currency:** each quote stores the currency it was priced in. The seeded base currency is never edited.

Worked example: a base fare of 100.00, H-7 urgency (+10%) and a nearly full flight (+15%), with a 10% promo and no seat fee, gives 100.00 → 110.00 → 126.50 → 113.85 before taxes. Each of those steps is one `fare_quote_line` row, and the simulator page shows the same steps for any inputs.

### How `pricing_rule` is set up

One row is one rule: a condition and a percentage change. If a quote matches the condition, its price moves by `adjustment_pct`. The rule's `rule_group` decides which condition columns it reads; every other condition column stays empty.

| Column | Meaning |
| --- | --- |
| `rule_group` | `urgency`, `load`, `month` or `period`. Rules compete only inside their own group |
| `name` | Label staff see, copied onto the quote line, e.g. "H-7" or "Songkran 2027" |
| `priority` | Check order inside a group: lowest number first, first match wins. Unique per group; staff reorder it with drag-and-drop |
| `min_days_out`, `max_days_out` | Urgency rules: days from simulated today to departure, both ends inclusive |
| `min_seats_left_pct`, `max_seats_left_pct` | Load rules: seats left as a percentage of the cabin, both ends inclusive |
| `month` | Month rules: departure month, 1 to 12 |
| `start_date`, `end_date` | Period rules: departure date range, both ends inclusive |
| `fare_class_id` | Optional: limits the rule to one fare class; empty means every fare class |
| `adjustment_pct` | +15 raises the price by 15%, −10 lowers it by 10% |
| `is_active` | Inactive rules are skipped |

Example rows (illustrative values):

| rule\_group | name | priority | Condition columns set | adjustment\_pct |
| --- | --- | --- | --- | --- |
| urgency | H-1 | 1 | `max_days_out` = 1 | +30 |
| urgency | H-3 | 2 | `min_days_out` = 2, `max_days_out` = 3 | +20 |
| urgency | H-7 | 3 | `min_days_out` = 4, `max_days_out` = 7 | +10 |
| load | Almost full | 1 | `max_seats_left_pct` = 20 | +15 |
| month | December | 1 | `month` = 12 | +10 |
| period | Songkran 2027 | 1 | `start_date` = 2027-04-11, `end_date` = 2027-04-17 | +20 |

A flight departing in 6 days with 15% of seats left matches H-7 and Almost full, so both apply; if it also departs in December, that adds the December rule too.

### Fare rules, fees and display currency

- **Validation:** a quote is rejected when the flight is unknown, cancelled or departed, when the fare class has no seats left in 3b, or when the departure is closer than the class's `min_advance_purchase_days`. Failures use the stable codes under API routes.
- **Cancellation and change fees:** `GET /fare-quotes/:id/fee` returns the fee from the fare rule frozen in the quote, so a later edit to the rule never changes an old booking. The fee is the flat amount plus the percentage of the quote total, capped at the total; a class that is not refundable or changeable says so instead of returning a fee.
- **Display currency:** the response can also carry the total converted with `rate_per_base`. The converted figure is never stored or charged.
- **Overweight baggage fee:** `GET /overweight-baggage-fee?fare_class_id=&route_id=&weight_kg=&heaviest_bag_kg=&extra_allowance_kg=` is called by 6 at bag drop, and by 10 when a passenger pays online. `weight_kg` is the passenger's total checked weight. Allowance = `free_allowance_kg` + `extra_allowance_kg` (the tier bonus feature 10 reads from 7, default 0). Billable kilograms = ceil(max(weight − allowance, 0)), and fee = billable kilograms × `rate_per_kg`. A route-specific rate overrides the fare class default row. If `heaviest_bag_kg` is over `max_bag_kg` the call is refused with `BAG_TOO_HEAVY`. The fee is not taxed and not stored as a quote line; the caller sends it to 5a for payment.

### Promo redemption

A quote does not use up a promo, because quotes are shared and can be requested again. A use is counted once, after payment, and the call is idempotent.

- `POST /promo-codes/:id/redemptions` (guard `Any`) takes `booking_ref` and `fare_quote_id`, and is called by 3b or 5a when a booking is paid. A repeat with the same `booking_ref` returns the first result and does not count again.
- The counter moves only while `used_count < max_uses`, in the same transaction as the `promo_redemption` insert. A full code returns `PROMO_INVALID` with `details.reason` = `exhausted`.
- `DELETE /promo-codes/:id/redemptions/:booking_ref` (guard `Any`) releases the use when the booking is refunded or payment fails.
- One use per booking, however many passengers it has.
- A code is valid when it is active and `valid_from <= simulated now < valid_to` (timestamps).

### Seat fee at check-in

`GET /seat-fees/price?cabin=&seat_type=&from_seat_type=` (guard `Any`) returns the amount, currency and taxes for a seat choice, and stores nothing. On an upgrade the passenger pays the difference between the new and the current seat type. Percent taxes apply to the seat fee; flat per-leg taxes are not charged again.

### Checkout with an expired quote

- Expiry is checked when payment starts (when 5a creates the payment), not when the Stripe webhook arrives, so a payment already in flight keeps its price.
- If the quote has expired, 3b or 5a requests a new quote with the same inputs. Same total: continue. Lower total: continue and show a notice. Higher total: stop, show the old and new price, and start payment only after the passenger confirms.
- If the new quote fails (no seats, flight cancelled or departed), checkout fails and 3b releases the seat hold.
- The seat-hold TTL in 3b must not be longer than `quote_hold_minutes`, or a seat can outlive its price.

## Data model

Sixteen tables carry Feature 4's data: thirteen for pricing and quoting, three for the financial report. Each quote stores the currency it was priced in (`fare_quote.currency`); `pricing_setting.base_currency` is seeded once and is not editable, and other currencies are display-only. `route_id` and `flight_id` point at feature 2's records with no foreign key, and are checked through its API.

| Table | Key columns | Notes |
| --- | --- | --- |
| `fare_class` | `code` (unique), `cabin`, `name`, `is_active` | e.g. Y / M / J; `cabin` matches the per-cabin seat counts in 3b |
| `fare_rule` | `fare_class_id` (unique FK), `min_advance_purchase_days`, `refundable`, `changeable`, `cancel_fee_flat`, `cancel_fee_pct`, `change_fee_flat` | One row per fare class; quote validation reads the advance-purchase window, 5b reads the fee fields |
| `base_fare` | `route_id`, `fare_class_id`, `amount` | The foundation price per passenger; unique per (route, fare class) |
| `pricing_rule` | `rule_group` (urgency, load, month, period), `priority`, `min_days_out`, `max_days_out`, `min_seats_left_pct`, `max_seats_left_pct`, start\_date, end\_date, `month`, `fare_class_id`, `adjustment_pct`, `is_active` | Empty condition columns mean "any"; within a group the first matching rule by priority wins, groups multiply |
| `seat_fee` | `cabin`, `seat_type`, `amount` | Flat fee by seat position (normal, exit row, extra legroom, taken from 9's seat map); unique per (cabin, seat type) |
| `overweight_baggage_rate` | `fare_class_id`, `route_id` (optional), `free_allowance_kg`, `rate_per_kg`, `max_bag_kg` (optional), `is_active` | Free allowance and fee per extra kg by fare class; an empty route means all routes, and a route row overrides it. Read by feature 6 at bag drop; unique per (fare class, route) |
| `tax_fee` | `code`, `name`, `kind` (tax, surcharge, fee), `calc_type` (flat, pct), `value`, `is_active` | Added after fare and discounts, shown as separate lines |
| `currency_rate` | `currency_code`, `rate_per_base`, `updated_at`, `updated_by` | Hand-typed fixed table; display conversion only |
| `promo_code` | `code`, `kind` (promo, corporate), `discount_pct`, discount\_amount, `valid_from`, `valid_to`, `max_uses`, `used_count`, `is_active` | Applied after the rules, before taxes; exactly one of discount\_pct / discount\_amount is set; valid\_from and valid\_to are timestamps |
| promo\_redemption | promo\_code\_id, booking\_ref, fare\_quote\_id, status (redeemed, released), redeemed\_at | One row per booking that used a code; unique per (promo code, booking\_ref) so a retry cannot count twice |
| `pricing_setting` | `key`, `value` | Editable constants, e.g. `quote_hold_minutes`, `base_currency` (seeded, read-only) |

| `fare_quote_line` | `fare_quote_id`, `seq`, `kind`, `label`, `rate_pct`, `amount`, `source_id` | The audit trail: base fare, each rule that fired, seat fee, promo, each tax/fee, in the order applied |
| `expense` | `category` (maintenance, staff, catering, other), `description`, `amount`, `incurred_on`, `payment_schedule_id`, `created_by` | Flat cost record, not a ledger |
| `payment_schedule` | `category`, `payee`, `description`, `amount`, `due_date`, `status` (scheduled, paid), `paid_on` | Marking a row paid creates its `expense`; "overdue" = due date before simulated today |
| `finance_monthly_summary` | `month`, `revenue_amount`, `refund_amount`, `maintenance_cost`, `staff_cost`, `catering_cost`, `other_cost`, `profit_amount`, `computed_at` | One row per month, recomputed by a scheduled job, read by feature 14 |

**Deliberately excluded from scope:** the extras catalogue and pre-paid extra bags (nothing in 3a or 5a consumes it yet), child/infant pricing (a quote is per passenger as booked), per-airport tax rules, double-entry accounting, and automatic cost feeds from features 8, 9 and 12 (costs are typed in by staff this iteration).

## Open questions

- **"Based on the position"** is read here as seat position (normal, exit row, extra legroom). If it meant route or city-pair position, `base_fare` already varies by route and `seat_fee` can be dropped.
- **Base currency** is USD (decided), seeded once and not editable afterwards; each quote stores the currency it was priced in, and all other currencies are display-only.
- **Revenue month** is the month the payment was captured, not the flight month. Flight-month revenue would need 5a to expose flight dates.
- **Quote sharing:** one quote per (flight, fare class, promo, seat type) is shared by all callers until it expires, so a second shopper sees a shorter remaining hold.

## SQL

```sql
-- All timestamps use TIMESTAMPTZ. Columns that mean "when, in the simulation"
-- (fare_quote.created_at / expires_at, paid_on, computed_at) carry no DEFAULT:
-- the app writes them from the shared simulation clock (feature 1), never now().
-- All money is NUMERIC(12,2) in the currency saved on the quote (fare_quote.currency); pricing_setting.base_currency is seeded once and never edited.
-- Soft delete on editable tables: deleted_at = now(); app queries filter
-- WHERE deleted_at IS NULL, and unique indexes are partial for the same reason.

CREATE TABLE fare_class (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  code TEXT NOT NULL,
  cabin TEXT NOT NULL CHECK (cabin IN ('economy', 'premium_economy', 'business', 'first')),
  name TEXT NOT NULL,
  is_active BOOLEAN NOT NULL DEFAULT true,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  deleted_at TIMESTAMPTZ
);
CREATE UNIQUE INDEX fare_class_code_uq ON fare_class (code) WHERE deleted_at IS NULL;

CREATE TABLE fare_rule (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  fare_class_id UUID NOT NULL UNIQUE REFERENCES fare_class (id),
  min_advance_purchase_days INT NOT NULL DEFAULT 0 CHECK (min_advance_purchase_days >= 0),
  refundable BOOLEAN NOT NULL DEFAULT false,
  changeable BOOLEAN NOT NULL DEFAULT false,
  cancel_fee_flat NUMERIC(12,2) NOT NULL DEFAULT 0 CHECK (cancel_fee_flat >= 0),
  cancel_fee_pct NUMERIC(5,2) NOT NULL DEFAULT 0 CHECK (cancel_fee_pct BETWEEN 0 AND 100),
  change_fee_flat NUMERIC(12,2) NOT NULL DEFAULT 0 CHECK (change_fee_flat >= 0),
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE TABLE base_fare (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  route_id UUID NOT NULL,            -- feature 2's route, no FK across modules
  fare_class_id UUID NOT NULL REFERENCES fare_class (id),
  amount NUMERIC(12,2) NOT NULL CHECK (amount > 0),
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  deleted_at TIMESTAMPTZ
);
CREATE UNIQUE INDEX base_fare_route_class_uq ON base_fare (route_id, fare_class_id) WHERE deleted_at IS NULL;

-- Rule engine. Conditions are ANDed; a NULL condition means "any".
-- Within one rule_group the first matching rule by priority wins (so the urgency
-- tiers H-1 / H-3 / H-7 / H-30 never stack); the winners of different groups multiply.
CREATE TABLE pricing_rule (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  rule_group TEXT NOT NULL CHECK (rule_group IN ('urgency', 'load', 'month', 'period')),
  name TEXT NOT NULL,
  priority INT NOT NULL,
  min_days_out INT,                  -- days between simulated today and departure
  max_days_out INT,
  min_seats_left_pct NUMERIC(5,2),   -- seats left / seats in the cabin, from 3b
  max_seats_left_pct NUMERIC(5,2),
  month SMALLINT CHECK (month BETWEEN 1 AND 12),   -- month of the departure date
  start_date DATE,                   -- pricing period: departure date range, inclusive;
  end_date DATE,                     -- the rule's name holds the label, e.g. 'Songkran 2027'
  fare_class_id UUID REFERENCES fare_class (id),   -- NULL = every fare class
  adjustment_pct NUMERIC(6,2) NOT NULL,            -- +15.00 = +15%, -10.00 = -10%
  is_active BOOLEAN NOT NULL DEFAULT true,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  deleted_at TIMESTAMPTZ,
  CHECK (rule_group <> 'urgency' OR min_days_out IS NOT NULL OR max_days_out IS NOT NULL),
  CHECK (rule_group <> 'load' OR min_seats_left_pct IS NOT NULL OR max_seats_left_pct IS NOT NULL),
  CHECK (rule_group <> 'month' OR month IS NOT NULL),
  CHECK (rule_group <> 'period' OR (start_date IS NOT NULL AND end_date IS NOT NULL AND end_date >= start_date))
);
CREATE UNIQUE INDEX pricing_rule_group_priority_uq ON pricing_rule (rule_group, priority) WHERE deleted_at IS NULL;

CREATE TABLE seat_fee (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  cabin TEXT NOT NULL CHECK (cabin IN ('economy', 'premium_economy', 'business', 'first')),
  seat_type TEXT NOT NULL CHECK (seat_type IN ('normal', 'exit_row', 'extra_legroom')),
  amount NUMERIC(12,2) NOT NULL CHECK (amount >= 0),
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  deleted_at TIMESTAMPTZ
);
CREATE UNIQUE INDEX seat_fee_cabin_type_uq ON seat_fee (cabin, seat_type) WHERE deleted_at IS NULL;

-- Excess checked-bag weight, charged at bag drop (feature 6). NULL route_id = default for the
-- fare class; a route row overrides it. fee = ceil(max(weight_kg - (free_allowance_kg + extra_allowance_kg), 0)) * rate_per_kg.
CREATE TABLE overweight_baggage_rate (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  fare_class_id UUID NOT NULL REFERENCES fare_class (id),
  route_id UUID,                     -- feature 2's route, no FK across modules
  free_allowance_kg NUMERIC(5,1) NOT NULL CHECK (free_allowance_kg >= 0),
  rate_per_kg NUMERIC(12,2) NOT NULL CHECK (rate_per_kg >= 0),
  max_bag_kg NUMERIC(5,1) CHECK (max_bag_kg > 0),   -- NULL = no limit; heavier is refused, not charged
  is_active BOOLEAN NOT NULL DEFAULT true,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  deleted_at TIMESTAMPTZ
);
CREATE UNIQUE INDEX overweight_baggage_rate_uq ON overweight_baggage_rate
  (fare_class_id, COALESCE(route_id, '00000000-0000-0000-0000-000000000000')) WHERE deleted_at IS NULL;

CREATE TABLE tax_fee (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  code TEXT NOT NULL,
  name TEXT NOT NULL,
  kind TEXT NOT NULL CHECK (kind IN ('tax', 'surcharge', 'fee')),
  calc_type TEXT NOT NULL CHECK (calc_type IN ('flat', 'pct')),
  value NUMERIC(12,2) NOT NULL CHECK (value >= 0),   -- amount if flat, percent if pct
  is_active BOOLEAN NOT NULL DEFAULT true,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  deleted_at TIMESTAMPTZ
);
CREATE UNIQUE INDEX tax_fee_code_uq ON tax_fee (code) WHERE deleted_at IS NULL;

-- Display only: shown = base amount * rate_per_base. Never used for charging or storage.
CREATE TABLE currency_rate (
  currency_code CHAR(3) PRIMARY KEY,
  rate_per_base NUMERIC(14,6) NOT NULL CHECK (rate_per_base > 0),  -- units of this currency per 1 base unit
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_by UUID NOT NULL REFERENCES staff (id)
);

CREATE TABLE promo_code (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  code TEXT NOT NULL,
  kind TEXT NOT NULL CHECK (kind IN ('promo', 'corporate')),
  discount_pct NUMERIC(5,2) CHECK (discount_pct > 0 AND discount_pct <= 100),
  discount_amount NUMERIC(12,2) CHECK (discount_amount > 0),  -- fixed amount in the quote's currency
  valid_from TIMESTAMPTZ NOT NULL,   -- simulated time; valid while valid_from <= now < valid_to
  valid_to TIMESTAMPTZ NOT NULL,
  max_uses INT,                      -- NULL = unlimited
  used_count INT NOT NULL DEFAULT 0,
  is_active BOOLEAN NOT NULL DEFAULT true,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  deleted_at TIMESTAMPTZ,
  CHECK (valid_to > valid_from),
  CHECK ((discount_pct IS NULL) <> (discount_amount IS NULL))   -- exactly one is set
);
CREATE UNIQUE INDEX promo_code_code_uq ON promo_code (code) WHERE deleted_at IS NULL;

-- Seeds: quote_hold_minutes, base_currency (base_currency is read-only after seeding; PUT /staff/settings/:key rejects it)
CREATE TABLE pricing_setting (
  key TEXT PRIMARY KEY,
  value TEXT NOT NULL,
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_by UUID REFERENCES staff (id)
);

CREATE TABLE fare_quote (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  flight_id UUID NOT NULL,           -- feature 2's flight, no FK across modules
  fare_class_id UUID NOT NULL REFERENCES fare_class (id),
  promo_code_id UUID REFERENCES promo_code (id),
  seat_type TEXT CHECK (seat_type IN ('normal', 'exit_row', 'extra_legroom')),
  currency CHAR(3) NOT NULL,                       -- currency the quote was priced in
  total_amount NUMERIC(12,2) NOT NULL,             -- per passenger, in the quote's currency
  seats_left_pct NUMERIC(5,2) NOT NULL,            -- inputs frozen at quote time
  days_to_departure INT NOT NULL,
  fare_rule_snapshot JSONB NOT NULL,               -- fare_rule row as it was; 5b reads fees from here
  created_at TIMESTAMPTZ NOT NULL,                 -- simulated time
  expires_at TIMESTAMPTZ NOT NULL                  -- created_at + quote_hold_minutes
);
CREATE INDEX fare_quote_lookup_ix ON fare_quote (flight_id, fare_class_id, promo_code_id, seat_type, expires_at DESC);

-- One row per booking that used a code. Redeem = one transaction: INSERT ... ON CONFLICT DO NOTHING, then, only if a row
-- was inserted, UPDATE promo_code SET used_count = used_count + 1 WHERE id = $1 AND (max_uses IS NULL OR used_count < max_uses).
-- Release sets status = 'released' and decrements used_count.
CREATE TABLE promo_redemption (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  promo_code_id UUID NOT NULL REFERENCES promo_code (id),
  booking_ref TEXT NOT NULL,         -- 3b's booking reference, no FK across modules
  fare_quote_id UUID REFERENCES fare_quote (id),
  status TEXT NOT NULL DEFAULT 'redeemed' CHECK (status IN ('redeemed', 'released')),
  redeemed_at TIMESTAMPTZ NOT NULL,  -- simulated time
  released_at TIMESTAMPTZ,
  UNIQUE (promo_code_id, booking_ref)
);

-- Append-only audit trail: base fare, each rule that fired, seat fee, promo, each tax/fee.
CREATE TABLE fare_quote_line (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  fare_quote_id UUID NOT NULL REFERENCES fare_quote (id) ON DELETE CASCADE,
  seq INT NOT NULL,
  kind TEXT NOT NULL CHECK (kind IN ('base', 'rule', 'seat_fee', 'promo', 'tax', 'surcharge', 'fee')),
  label TEXT NOT NULL,               -- rule name copied at quote time
  rate_pct NUMERIC(6,2),             -- set for rule, promo and pct taxes
  amount NUMERIC(12,2) NOT NULL,     -- signed change this line made
  source_id UUID,                    -- pricing_rule / promo_code / tax_fee id
  UNIQUE (fare_quote_id, seq)
);

CREATE TABLE payment_schedule (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  category TEXT NOT NULL CHECK (category IN ('maintenance', 'staff', 'catering', 'other')),
  payee TEXT NOT NULL,
  description TEXT,
  amount NUMERIC(12,2) NOT NULL CHECK (amount > 0),
  due_date DATE NOT NULL,
  status TEXT NOT NULL DEFAULT 'scheduled' CHECK (status IN ('scheduled', 'paid')),
  paid_on DATE,                      -- simulated date; overdue = scheduled and due_date < simulated today
  created_by UUID NOT NULL REFERENCES staff (id),
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  deleted_at TIMESTAMPTZ,
  CHECK ((status = 'paid') = (paid_on IS NOT NULL))
);

CREATE TABLE expense (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  category TEXT NOT NULL CHECK (category IN ('maintenance', 'staff', 'catering', 'other')),
  description TEXT NOT NULL,
  amount NUMERIC(12,2) NOT NULL CHECK (amount > 0),
  incurred_on DATE NOT NULL,         -- decides which month it lands in
  payment_schedule_id UUID REFERENCES payment_schedule (id),
  created_by UUID NOT NULL REFERENCES staff (id),
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  deleted_at TIMESTAMPTZ
);
CREATE INDEX expense_month_ix ON expense (incurred_on, category) WHERE deleted_at IS NULL;

-- Rebuilt by a scheduled job and on demand; feature 14 reads it instead of querying live tables.
CREATE TABLE finance_monthly_summary (
  month DATE PRIMARY KEY CHECK (EXTRACT(DAY FROM month) = 1),
  revenue_amount NUMERIC(14,2) NOT NULL DEFAULT 0,   -- captured payments from 5a
  refund_amount NUMERIC(14,2) NOT NULL DEFAULT 0,    -- refunds from 5b
  maintenance_cost NUMERIC(14,2) NOT NULL DEFAULT 0,
  staff_cost NUMERIC(14,2) NOT NULL DEFAULT 0,
  catering_cost NUMERIC(14,2) NOT NULL DEFAULT 0,
  other_cost NUMERIC(14,2) NOT NULL DEFAULT 0,
  profit_amount NUMERIC(14,2) NOT NULL,
  computed_at TIMESTAMPTZ NOT NULL,                  -- simulated time
  CHECK (profit_amount = revenue_amount - refund_amount - maintenance_cost - staff_cost - catering_cost - other_cost)
);
```
